# 02 源码输入与预处理

更新：2026-10-27。实现需求：ENV-03、SRC-01、SRC-02、TPL-01、QRY-01、SCAN-01、SCAN-03。

## 输入与登记

| 来源 | 接口 | 持久化证据 |
| --- | --- | --- |
| 本地 Java 目录 | `POST /sources/local` | realpath 身份、实际 Java 内容指纹、文件数和字节数 |
| 公开 GitHub HTTPS 仓库 | `POST /sources/github` | 规范化 URL、本次 HEAD、Java 指纹、应用持有目录 |
| 重新打开 | `POST /sources/open` | 按 projectId 找记录，重新扫描比较指纹，不假设保存路径仍有效 |

Git/rg 检测区分 available、missing、failed。检测是只读操作，缺失时给官方安装提示和重试入口，不自动安装或修改全局 Git。安装后旧应用可能仍持有旧 PATH，需要重启应用。

重复来源要求明确选择 reject、open 或 new：open 不更新旧副本；new 创建独立记录/路径。下载后不会自动调用模型。

## 文件范围和版本

源码扫描使用 lstat 识别链接，realpath 统一身份并检查目录边界；不跟随源码树内链接或目录联接。当前限制为最多 2000 个 Java 文件、单文件 2MiB、总计 20MiB、深度 32、目录项 20000，超限明确失败，不静默截断登记指纹。

对纳入范围的每个 Java 文件计算 SHA-256，按相对路径排序后组合内容哈希再求 SHA-256。遍历顺序不影响结果，路径或内容变化会改变登记指纹。Git HEAD 与内容指纹分别保存，不能相互代替；指纹不涵盖所有资源，也不是不可变文件系统快照。

## 下载生命周期

GitHub 输入白名单拒绝任意主机、SSH、file 协议、凭据 URL 和路径穿越。Git 使用 spawn 参数数组，隔离全局配置、凭据助手和额外程序行为；只清理本次拥有的进程树，不按名称结束所有 Git。

下载使用独占临时目录，`depth=1`，验证后 rename，再事务登记。失败/取消清理自己的临时副本；DB 登记失败清理自己的已准备目录。rename 与 SQLite 不能组成跨资源事务，进程强制崩溃仍可能留下未登记目录，目前没有完整崩溃恢复账本。子模块、LFS 实体和完整历史不在下载承诺内。

## 规则与基础查询

`service/rules/builtin.ts` 统一维护 SQL 注入、命令注入和路径遍历候选规则及版本。危险 API 命中只形成线索，不能直接判 dangerous。

| 接口 | 功能 |
| --- | --- |
| `GET /rules` | 内置规则与版本 |
| `POST /code/search` | 登记源码中的 rg 字面量文本搜索，限制输出 |
| `POST /code/read` | projectId + 相对路径 + 行范围受控读取 |
| `POST /code/risks` | 三类规则候选及参数位置 |

查询检查登记指纹，拒绝变化源码和越界路径；缺 rg、取消、无匹配和结果截断分别反馈。工具不能接收任意 shell、SQL 或项目根目录替换。

## 预处理

`POST /chains/prepare` 每次创建新 runId，绑定源码指纹和规则版本。Java CST 索引提取方法和调用位置，从候选 Sink 反向有界展开；HTTP 注解方法是候选入口。重载歧义、动态分派及外部依赖保留 unresolved，不能宣称类型绑定已确认。

| 预算 | 默认 | 硬上限 |
| --- | --- | --- |
| 候选 Sink 结果 | 100 | 100 |
| 路径深度 | 16 | 32 |
| 展开状态 | 512 | 2000 |
| 路径数 | 100 | 100 |

递归按当前路径检测，保留重复步骤和 recursion 标记，不用全局 visited 误删共享分支。达到预算记录 depth-limit、node-limit、path-limit 等覆盖限制。单路径 Agent 审阅目前最多 16 步。

扫描状态为 scanning、ready、partial、empty、failed。零命中只表示支持范围内没有候选；partial、解析回退和未解析调用必须保留告警。完成图登记时，调用边、路径、有序步骤及扫描结果原子提交。

代码入口：`service/sources/`、`service/query/`、`service/rules/`、`service/scanning/`、`service/chains/paths.ts`。数据关系见 [03 数据模型与持久化](03.数据模型与持久化.md)。
