# 03 数据模型与持久化

更新：2026-10-29。SQLite schema v12；实现DB-01～DB-04及事件/报告、源码快照、发送许可、手工来源、独立人工复核和可验证恢复持久化。

## 存储约束

`service/storage/database.ts` 封装 Node DatabaseSync。数据库位于应用数据根目录的 `storage/audit.sqlite3`。启用并读回外键，busy_timeout 为 1000ms；事务使用 BEGIN IMMEDIATE，仅允许同步回调，禁止嵌套事务和事务结束后继续写入。

迁移追加执行，保留已发布 SQL 与 SHA-256 校验和；DDL、迁移记录和 user_version 同事务提交，失败回滚。application_id 区分应用库，不重置来源未知或版本更高的数据库。

## path_steps：有序引用与证据

| 字段 | SQLite 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| path_id / step_index | TEXT / INTEGER | 是 | 联合主键；step_index 从 0 开始 |
| edge_uid | TEXT | 是 | 引用共享调用边 |
| run_id / project_id | TEXT | 是 | 复合外键校验作用域 |
| dangerous | INTEGER | 否 | 当前步骤判断，未知为 NULL |
| taint_in_json / taint_out_json | TEXT | 是 | 本路径步骤的污染输入输出，JSON 数组 |
| evidence_json | TEXT | 是 | 实际文件范围和原文引用，JSON 数组 |
| defense_summary | TEXT | 是 | 已有防护说明，可为空字符串 |
| propagation_json | TEXT | 是 | 来源、参数、赋值、返回值、字段、防护六项核查的 JSON |

共享边只保存一次，不同路径通过各自步骤保存上下文。例如两条入口共享同一末端调用时，可有 3 条边、2 条路径和 4 条步骤；不能用函数 parentId 树替代图与路径关系。

## 尝试与事件

path_attempts 以 path_id 为主键，保存最新 attempt、model_config_id、phase、时间和 error_code。领取事务先检查 pending 或允许明确重试的状态，再递增 attempt 并清空本次路径结果。旧 attempt 的迟到回写被拒绝。

analysis_sessions 保存 session_id、project_id、run_id、chain_id、attempt_id、model_config_id、state、min_event_id 与时间；UNIQUE(chain_id,attempt_id)。stream_events 主键为 (session_id,id)，持久化 event、data_json 和时间。重连读取原记录，不生成新的业务结果。

analysis_events 以 event_id 为主键，UNIQUE(run_id,seq)，保存 chain_id、type、summary/summary_missing、工具调用身份、耗时、脱敏 payload_json 与截断标记。任务级事件不强行归入某条链。

路径结果、逐步证据、任务状态、分析事件与 SSE 终态同事务提交。SQLite 操作有限重试，持续失败且连故障都不能写入时显式返回持久化状态未确认；下次服务启动恢复未完成尝试。

## 报告快照与迁移历史

人工复核写入 path_review_versions，不改 call_paths、path_steps 或源码字节。保存事务同时检查 expectedRevision 与当前机器结果SHA-256基线；更新人工记录时追加revision，历史UPDATE/DELETE被触发器拒绝。机器重跑后旧记录保留，读取时派生stale。尚无记录时返回未复核/revision=0，不提前写入占位行。

reports 保存 id、run_id、project_id、file_path、pending/ready/failed、summary、created_at、generated_at、error_message。summary_json 在正式生成时保存同一快照的 statistics、stageReport、sha256 和 generatedAt；旧记录缺少的字段保持未知，不伪造为 0。重试分析不修改已生成报告快照。

v11新增format=html/json及三维filter_json。summary_json额外固定snapshotKey、stageReasons、reviewCounts、totalPaths。旧记录默认HTML/全量，未保存的新摘要与计数不回填。报告快照中的机器与人工统计独立；筛选与文件生成共用同一读取入口。
