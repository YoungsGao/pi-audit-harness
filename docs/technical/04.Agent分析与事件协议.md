# 04 Agent 分析与事件协议

更新：2026-10-29。实现 AGT-01～AGT-04、API-02、UI-05、RUN-03 对应的有界分析、传播核查与事件回放，并接入源码快照和发送授权。

## 执行流程

CallChainService 接受项目、任务、路径与模型配置身份；PathAnalysisService 原子领取路径，调用真实 Pi 会话。Agent 通过唯一受控工具 audit_read_step 按 stepIndex 读取当前路径源码，逐轮返回 continue 或 finish 决策。finish 结果通过结构与证据检查后才能提交。

领取前验证项目快照与目标模型的发送许可；真实 streamFunction 委托前再次验证实际配置、请求预算并保存发送尝试。拒绝时不进入原供应商传输。手工风险点复用相同流程，调查说明作为待分析数据传入。详见 [08 四项增强](08.配置授权快照与手工调查.md)。

单次模型回复可并行提出多个取证调用。受控源码查询在本路径范围内串行执行，避免并行读取冲突触发 QUERY_BUSY；工具调用次数仍在读取前逐项检查，不能绕过预算。

| 预算 | 默认/当前上限 |
| --- | --- |
| 决策轮次 | 4 |
| 工具调用 | 24 |
| 实际模型请求 | 28 |
| Agent 时长 | 110 秒 |
| 单路径外层时长 | 正式 Agent 模式 120 秒 |
| 无新增证据计数 | 3 |
| 累计证据文本 | 65536 字节 |
| 串行待办 | 默认每批 10 条，参数硬上限 100；批时限在路径之间检查 |

Pi SDK 自动重试和自动压缩在该循环内关闭。服务只允许一个活动分析工作；关闭服务会取消并等待它。模型、Git 和整次分析不无限自动重启。

任务还固定所选知识模板和项目要求，真实请求通过 auditKnowledge 使用该副本。文档是参考数据，不增加工具权限或跳过证据验证；发送范围包含材料摘要。详见 [09 模板与审查配置](09.审计知识模板与项目审查配置.md)。

预处理取得的 JDT-LS confirmed 关系随固定路径进入真实 Pi 请求。它只说明静态目标已定位，Agent仍需逐步取证；语义降级、外部依赖与预算缺口保存在扫描告警中，不由空结果推导安全。详见 [10 统一查询与Java语义服务](10.统一代码查询与Java语义服务.md)。

## 决策与证据校验

模型只能指定步骤编号，不能指定根目录、任意文件或命令。工具携带 runId 从绑定的固定快照读取实际源码，并保存独立文件范围。重复内容按哈希识别无进展；新增内容重置无进展计数。

每步保存 taintIn、taintOut、reason、quotes 和六项检查：source、argumentMapping、assignment、returnValue、field、defense。检查状态为 supported、blocked、unknown 或 not_applicable。引用必须是实际读到的单个文件范围内原文，不能用合成标题或跨文件拼接字符串证明传播。

危险结论要求逐步风险证据、前后污染引用和来源支持；阻断结论要求对应防护证据。来源不是已识别 HTTP 入口候选、覆盖不足或关键检查未知时，保守保留 unknown，不把函数名、模型置信度或字段齐全当成语义证明。

调查状态与风险维度分离：failed/unresolved 不能计为 safe；SSE completed 仅表示会话执行结束，业务路径可能仍为 unresolved/unknown。

## 固定业务接口

普通接口返回 `{ok,requestId,data/error}`，全部经过本地认证及输入/输出校验。

| 路径 | 请求关键字段 | 行为 |
| --- | --- | --- |
| `POST /chains/analyze` | projectId,runId,pathId,modelConfigId | 明确启动单路径分析 |
| `POST /chains/analyzePending` | projectId,runId,modelConfigId,maxPaths? | 串行领取 pending，失败后停止 |
| `POST /chains/runState` | projectId,runId | 数据库任务阶段与统计，故障时返回未确认 |
| `POST /chains/events` | projectId,runId,pathId?,afterSeq?,limit? | 任务级有序过程记录 |
| `POST /chains/history` | projectId,runId,pathId,sessionId?,afterId? | 最近 20 次尝试元数据和最多 50 条原始帧，只读 |
| `POST /analyze` | projectId,runId,chainId,modelConfigId,sessionId?,afterId? | 启动/附着实时事件；携带会话时只读重连 |

调用链列表、详情、统计接口分别为 `/chains/list`、`/chains/detail`、`/chains/statistics`，分页与作用域从 SQLite 读取。

## SSE 协议

响应为 `text/event-stream`。每帧包含 event、id、data 三行，data 是 JSON；心跳为注释 `: ping`，无业务 ID。UTF-8 和 CRLF 可跨网络块拆分，解析器逐块组合，拒绝超大帧、游标跳号、会话错配、状态错配和终态后追加。

| event | data.type | data.status |
| --- | --- | --- |
| queued | process | queue |
| analyzing | process | analyze |
| thoughts_execute | thinking | analyze |
| tool_call_info | process | analyze |
| completed | result | completed |
| failed | result | error |
| timed_out | result | timeout |
| stopped | result | stop |
| cancelled | result | cancel |

data 包含 projectId、runId、chainId、sessionId、attemptId、type、status、message、summaryMissing、details。模型隐藏推理不输出，缺少公开摘要明确标记；payload 有脱敏、字节和深度边界。

sessionId 区分分析尝试，id 是会话内游标，connectionId 区分传输连接。重连原会话按 afterId 补发原始 ID，不重新调用模型。游标超前返回 SSE_CURSOR_AHEAD；不属于当前作用域返回 SSE_SESSION_MISMATCH；早于保留边界返回 SSE_HISTORY_EXPIRED。

网络 EOF 不是成功条件。即使服务端开始时声明会话已结束，未收到终态仍是中断。仅当按已收到的最后游标重连，服务端确认相同 last-event-id 且无新事件时，允许合法空重连。

## 故障收敛

RUN-01/RUN-02已实现主动停止和证据驱动恢复，详见[12 停止与恢复](12.任务停止与可验证会话恢复.md)。停止先保存屏障并阻止新工作，再等待本地操作退出；stage沿用interrupted，run_controls区分受理、等待、已停止。服务重启只整理遗留状态，用户核对清单后才继续。

路径领取、attempt、SSE会话与恢复绑定同事务；完整轮次保存原生Pi消息和宿主状态。恢复核对原快照、固定知识、规则、模型配置及工具回执，沿用累计请求/工具/轮次预算。会话可重开则native，不可用则明确重建/重跑；已提交路径不重复执行，合法finish检查点重新校验后可无新增模型请求提交。

SQLite 写操作最多初次加两次重试，间隔 50/100ms；不重复模型请求。结果失败时尝试写失败终态；连失败状态也不可写则返回 ANALYSIS_PERSISTENCE_FAILED，停止领取新任务，页面标记数据库状态未确认。磁盘恢复后重启，recover 收敛未结束尝试。

断开SSE不取消后台分析，重连只补发旧记录；主动停止/恢复使用独立固定动作。页面每轮最多手动重连2次。恢复与显式重新分析创建新attempt和SSE会话，旧会话与历史报告不改写。恢复使用原任务快照，若要审计新源码则重新登记并创建新任务。
