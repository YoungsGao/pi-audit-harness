# BUILD-01 项目构建技术方案

版本：v0.2｜日期：2026-10-19｜状态：待评审｜平台：Windows x64

**目标：跑通“启动客户端 → 本地服务就绪 → 保存模型配置 → Pi 真实回复 ping → 重启后配置保留 → 退出时服务结束”。**

## 需求背景

依据[当前需求看板](https://youngsgao.github.io/pi-audit-harness/docs/prd/index.html)，本方案覆盖全部 7 个子需求：

| 子需求 | 本阶段交付 |
| --- | --- |
| ENV-01 | 主窗口、四页导航、受控桥接、真实服务状态与失败原因 |
| API-01 | 本地服务启动、健康检查、认证和退出清理 |
| ENV-02 | 固定版本 Pi 接入、应用扩展加载与调用适配 |
| DB-01 | SQLite 初始化、迁移、事务与持久化 |
| DB-02 | 项目元数据、模型配置及凭据引用 |
| MOD-01 | 手动新增、修改、选择模型；保存不调用模型 |
| MOD-03 | 用户主动触发真实 ping，显示回复、耗时或错误 |

源码导入、污点分析和报告生成在后续需求实现。

## 模块与流程

使用 TypeScript + Electron + React；主进程通过 `utilityProcess` 管理独立本地服务，SQLite 和 Pi 由服务统一访问。

```text
React 页面 → preload 固定方法 → Electron 主进程
                                  ├─ 服务生命周期与凭据管理
                                  └─ 本地 HTTP → 服务进程 → SQLite / Pi → 模型服务
```

- **页面与 preload：** 展示配置、状态和结果；只暴露明确的方法。
- **主进程：** 创建窗口，启停服务，管理凭据，代理 HTTP 请求。
- **本地服务：** 校验请求，访问数据库，调用 Pi，归一化结果和错误。

服务代码建议放在 `desktop/src/service/`，单独构建 ESM 入口；Pi 先固定为现有接口基线 1.2.0。SQLite 驱动建议 better-sqlite3，先验证 Electron ABI、Pi 加载和构建后运行，再锁定依赖版本。

关键流程：

1. **启动：** 窗口显示 starting → 服务初始化 SQLite/Pi → 回环地址动态端口监听 → 主进程检查 `/health` → 显示 ready 或 failed。
2. **保存：** 校验配置 → 主进程加密保存凭据 → 数据库保存非敏感字段和引用；不访问模型服务。
3. **测试：** 按所选配置创建临时 Pi 会话 → 发送固定 ping → 返回非空最终回复和耗时 → 释放会话。
4. **退出：** 停止新请求，取消在途测试，关闭数据库与服务；超时只终止本客户端创建的进程。父进程心跳丢失时服务自行退出。

## 接口设计

页面使用 `window.audit`，新增配置查询/保存/选择、服务状态订阅和模型测试方法；不暴露通用 IPC、任意 URL 或命令执行能力。

| 本地 HTTP | 用途 |
| --- | --- |
| GET /health | 检查本地服务，不测试模型 |
| GET /model-configs | 查询模型配置 |
| POST /model-configs、PATCH /model-configs/:id | 新增或修改非敏感配置及凭据引用 |
| PUT /settings/model | 保存选中的配置 ID |
| GET /projects | 查询项目元数据；导入在后续实现 |
| POST /test | 接收 modelConfigId，通过 Pi 执行一次固定 ping |

服务仅监听 `127.0.0.1`，每次启动生成认证令牌；令牌由主进程持有，不交给页面。响应统一包含 `ok`、`requestId`、`data` 或 `error(code/message/retryable)`；后续有项目和任务时传递 projectId/runId。

Pi 使用显式 ModelRuntime 和应用专属目录。ping 禁用工具和项目资源加载，不发送源码、不自动发现模型或切换模型。首个兼容协议建议为 OpenAI-compatible chat completions，其他协议单独验证。

## 数据结构

运行数据放在 `app.getPath('userData')`，数据库仅由服务访问，使用迁移、参数绑定和事务。

| 表 | 核心字段 |
| --- | --- |
| schema_migrations | 迁移版本、执行时间 |
| projects | 项目 ID、名称、来源类型、路径、Git URL（可空）、源码版本 |
| model_configs | 配置 ID、名称、Base URL、模型 ID、协议、secret_ref、配置版本 |
| app_settings | 当前选中的模型配置 ID |

API Key 不进入 SQLite、普通日志或配置返回值。建议由主进程使用 safeStorage 异步加密，数据库只保存凭据引用；是否满足“系统凭据存储”口径见待确认项。

更新凭据时先写新引用，再提交数据库。明确回滚才清理新凭据；响应超时则先核对是否已提交，避免误删有效凭据。配置版本用于拒绝旧更新，并防止旧 ping 结果覆盖新配置。

## 异常处理

- 服务状态区分 starting / ready / failed / stopping / stopped，显示失败阶段和原因；ready 不代表模型已连通。
- 模型测试单独维护状态；鉴权、模型 ID、额度、网络、超时和空回复均给出明确错误。
- 测试采用单请求互斥和有限超时，取消后释放会话；不自动重试或更换模型，SDK 重试策略也需明确关闭。
- 数据库迁移和凭据失败保留旧数据，不清库、不回退明文。日志只保留脱敏标识、阶段、错误码和耗时。

## 测试验收

开发顺序：**运行环境兼容验证 → 服务启停与状态 → 数据库/凭据 → 模型配置页 → Pi 真实 ping → 联合验收。**

| 验收点 | 通过条件 |
| --- | --- |
| 客户端 | 开发和构建后均能启动，四页导航、IPC 和错误提示可用 |
| 本地服务 | 真正启动、健康检查、失败重试和退出清理通过；无认证请求被拒绝 |
| 存储与凭据 | 迁移失败可回滚，项目/配置重启后保留，Key 不以明文落库或输出 |
| 模型配置 | 新增、修改、选择生效；保存不触发模型请求 |
| Pi 与测试 | 指定配置产生真实请求，非空最终回复即通过，不要求逐字返回 pong；错误、超时和重复点击可控 |
| 扩展 | 应用自带扩展真实加载，调用和输出可捕获；跨阶段范围见下节 |

离线测试验证数据库、状态和错误；真实模型联调由用户主动执行，记录源码版本、依赖、模型、请求数、结果及耗时。假响应不替代真实 ping。

最终演示：冷启动 → 服务就绪 → 保存配置 → 真实 ping → 退出 → 重启 → 原配置再次测试 → 退出。全部约定验收完成后再标记 BUILD-01 完成。
