## 2. 克隆后的启动与操作

使用 Windows x64、Node.js 24 与 npm；Git 和 rg 由用户安装，应用不修改用户 Git 设置。

```powershell
git clone https://github.com/YoungsGao/pi-audit-harness.git
cd pi-audit-harness/desktop
npm ci
npm run dev
```

先在“项目管理”选择 `desktop/tests/fixtures/scan-java` 的绝对路径并导入。再在“审计分析”选择项目，手动预处理。示例应得到 2 条候选路径、1 个独立 Sink、4 条必要调用边和 6 条路径步骤。

模型配置不是预处理的前提。需要调用模型时：填写名称、Base URL、模型 ID、API Key → 保存 → 在“当前选择”应用配置 → 手动测试 → 在审计工作台确认“本次分析模型” → 开始分析当前路径。

生产代码与测试使用不同数据根目录。正式服务启动日志显示 `userData/runtime` 下的数据根目录，SQLite 文件为该目录的 `storage/audit.sqlite3`。密钥在 Windows 凭据管理器中，不随 Git 提交或换机器复制。

## 3. 进程与接口边界

```text
React 页面
  → window.audit 固定方法
  → preload IPC
  → Electron main：检查窗口/frame、校验 DTO、代理固定路由
  → 127.0.0.1 动态端口 + 启动令牌
  → TypeScript utilityProcess
      ├─ SQLite：项目、模型引用、候选图、路径、证据
      ├─ Node 文件 API / Git / rg
      └─ Pi SDK → 用户显式选择的模型服务
```

关键代码位于 `main/service-manager.ts`：使用 `utilityProcess.fork()` 创建本次拥有的服务进程，启动随机认证令牌，接到监听消息后再实际检查健康接口。进程存在不代表服务 ready；健康检查成功也不代表外部模型连通。

前端既不持有本地服务认证令牌，也不获得任意 HTTP URL、SQL 或 shell 执行接口。主进程的 `assertClient` 验证调用来自应用窗口和主 frame，随后由固定客户端方法访问本地服务；主进程还对成功响应校验字段与归属。

退出时先停止新请求，取消 Pi / 文件操作，等待受控任务释放，然后关闭数据库。服务通过父进程心跳识别失联；只清理本次创建的服务和命令进程。

## 4. 模型配置：身份、快照、连接测试

当前协议固定为 `openai-completions`，即 OpenAI Chat Completions 兼容接口，并非旧式文本 completions。仅支持 Responses 的服务需要新增协议适配，不能靠改 URL 后缀解决。

| 字段 | 含义 |
| --- | --- |
| name | 本地展示名称 |
| baseUrl | 服务基础 URL；不携带用户名、密码、查询参数或 fragment |
| modelId | 供应商支持的准确模型 ID |
| configId / revision | 本地配置身份与乐观并发版本 |
| secret_ref | 后端保存的 Windows 凭据引用，绝不作为模型 Key 返回页面 |

`ModelsPage` 把“正在编辑”“已保存配置”“当前选择”分别管理。保存不会自动切换模型；空 Key 表示保留已有密钥，修改 Base URL 则必须重新输入该地址的密钥。调用时通过 `resolveModelConfig()` 取得固定版本的配置/凭据快照，避免在途请求跟随后续配置修改。

`pi-session-factory.ts` 用应用私有目录和显式 ModelRuntime 注册一个 `audit-configured` provider；不读取用户 Pi 模型文件，不自动联网发现或替换模型。ping 与路径审阅共用保存的配置解析和会话工厂。

### 连接成功与审阅失败为什么可以同时出现

ping 只发送固定文本，不带源码；单路径审阅发送规则、多个源码片段并要求 JSON 和逐步原文引用。连接测试成功只证明该次请求收到了非空文本。

当前固定参数：ping 的 Pi 操作上限 15 秒；路径审阅的 Pi 操作上限 60 秒，路径全流程上限 90 秒。`MODEL_TIMEOUT` 也可能来自上游 408/504/timeout，单看错误码不能分辨哪一层超时。工厂描述使用 8192 上下文、512 最大输出 token 和关闭推理等级，界面暂不支持调整；这不是供应商模型真实能力的自动探测结果。

用户提供的截图已显示一次指定模型的非空 ping 回复；随后路径审阅出现过 `MODEL_TIMEOUT`。这两项是人工联调观察，不能替代自动回归，也不证明稳定性或漏洞判断质量。本次提交未更改超时和模型协议，未再次请求付费供应商。

## 5. SQLite：迁移、事务、约束

正式驱动是 Node 内置的 `DatabaseSync`，不是原方案建议的 better-sqlite3。这样随 Node/Electron 使用 SQLite，无需新增该原生模块的 ABI 构建步骤。

`storage/database.ts` 初始化后显式启用并读回 `PRAGMA foreign_keys`，设置有限 busy timeout，关闭外部扩展加载。所有业务参数通过预处理语句绑定：

```typescript
this.connection.prepare(sql).run(...params)
```

绑定参数解决 SQL 数据值与语句结构的分离，不能用来放行任意表名或任意客户端 SQL。因此数据库连接和 SQL 接口仅供服务内部使用。

`transaction()` 执行 `BEGIN IMMEDIATE`，拒绝嵌套事务与 async 回调，回调完成后使事务 session 失效。不要在 SQLite 同步事务中 `await` Git、网络或系统凭据操作。

当前迁移：

| 版本 | 新增职责 |
| --- | --- |
| v1 | 项目、模型、任务、边、路径、步骤、报告与索引 |
| v2 | 项目 Git 元数据、模型协议/时间、凭据清理账本 |
| v3 | 显式模型选择及选择版本 |
| v4 | source_imports，保存登记来源、Java 内容指纹、文件数和字节数 |
| v5 | 调用位置、参数、路径状态和上下文证据扩展 |
| v6 | scan_runs、path_attempts，保存预处理状态和审阅尝试 |

历史迁移有校验和，只能追加，不能改已发布 SQL。迁移失败整体回滚，拒绝未知/过新数据库，不自动清库。复合外键 `(run_id, project_id)` 防止把其他项目或任务的调用边拼进当前路径。

## 6. 凭据与 SQLite 为什么要有补偿账本

`WindowsCredentialStore` 使用固定 PowerShell/C# 脚本访问 Windows Credential Manager。命令参数不包含 Key，输入通过私有 stdin 管道传递；不向普通日志输出 Key、原始凭据输出或供应商异常正文。

SQLite 和系统凭据库不能合并为一个事务。`MetadataService.saveModel()` 的关键顺序是：

```typescript
if (newRef) this.repository.prepareCredential(newRef)
if (newRef) await this.vault.write(newRef, input.apiKey!)
const model = this.repository.commitModel(input, id, reference, newRef)
await this.cleanupOne()
```

先记录新引用的待清理意图，写系统凭据，再事务提交模型引用。数据库失败时清理新引用；成功后旧引用进入清理账本。恢复和后续操作可重试清理，每次清理前都核对引用是否仍在使用。凭据删除失败不应把已提交的配置伪装成保存失败。

这段代码适合学习“跨资源补偿”与“明确提交结果”：既不假称跨资源原子，也不在未知提交结果下盲目删除有效密钥。

## 7. ENV-03：只读检测与进程管理

`detectTool()` 用 `git --version` / `rg --version`，区分：available 为执行并格式检查成功；missing 为 ENOENT；failed 为存在但执行失败、超时或格式不符。

Node 继承应用启动时的 PATH。安装 Git 后，已打开的应用仍可能持有旧 PATH；重启应用再检测。rg 缺失不阻止本地目录导入，但会影响依赖 rg 的查询/预处理能力。

`sources/process.ts` 的核心调用：

```typescript
spawn(executable, args, {
  cwd: options.cwd,
  env: options.env,
  windowsHide: true,
  stdio: ['ignore', 'pipe', 'pipe']
})
```

不启用 shell，空格、分号、`&` 不会拼接成额外命令；仍须验证可执行程序及业务参数。普通命令默认 4 秒，stdout/stderr 合计最多 1MiB；公开 clone 上限 60 秒。Windows 取消仅针对本次 PID 使用 `/T` 终止子树，不能按名称结束全机 Git。

## 8. SRC-02：本地目录、读取范围与指纹

`scanJava()` 不只判断目录存在，还要找到真实可读的 Java 文件。先 `realpath` 统一根目录身份，使用 `lstat` 识别并跳过源码树中的符号链接/目录联接，排除 `.git`、`target`、`build` 等目录。

限制为：深度 32、目录项 20000、Java 文件 2000、单文件 2MiB、Java 总计 20MiB。超限明确失败，不静默截断后宣称完整登记。

每个 Java 文件计算 SHA-256，再对排序后的 `[relativePath, contentHash]` 记录组合计算 SHA-256：

```typescript
const sha256 = createHash('sha256').update(content).digest('hex')
hashes.push(JSON.stringify([filePath, sha256]))
const stamp = 'java-sha256:' +
  createHash('sha256').update(hashes.sort().join('\n')).digest('hex')
```

排序使遍历顺序不影响指纹；相对路径或内容改变会改变指纹。本地输入不要求 Git，Git 来源另外保存实际 HEAD 和 dirty。Java 指纹不是完整仓库快照，也不能替代 Git commit；配置、资源、未读取文件和扫描期间的并发修改仍有边界。

`SourceRepository.save()` 在同一事务写 `projects` 和 `source_imports`。重开时按 projectId 找记录、重新扫描、比较当前/登记指纹。数据库保存路径不意味着目录永远存在或内容不变。

## 9. SRC-01：下载的生命周期

仅允许 `https://github.com/owner/repo`，拒绝 SSH、file、其他主机、URL 凭据、查询参数和分支网页路径。规范化 URL 后才进行来源判重。

下载过程：明确重复选择 → 检测 Git → 在应用 repositories 下创建独占 `.partial-*` → clone → Java 校验 → 读取实际 HEAD/dirty → rename 为随机正式目录 → SQLite 事务登记。

clone 使用 `--depth=1 --single-branch --no-tags --no-recurse-submodules`，屏蔽全局 Git 配置、凭据助手、URL 重写、额外 hooks/filter，并关闭凭据交互。这样也可能限制依赖全局代理的用户环境；浅历史不支持完整历史分析，不取子模块/LFS 实体，也不是严格下载字节配额。

重复来源默认拒绝。“打开已有”不更新 checkout，“下载新副本”生成新目录与 ID，不执行 pull/reset 或覆盖旧项目。

rename 与 SQLite 不能共享事务。DB 失败后清理本次拥有的目录；强制崩溃仍可能留下未登记目录，尚无下载崩溃恢复账本。登记成功不自动调用模型或生成成功审计结论。

## 10. 调用链、步骤与前端统计

调用关系是图，不能只用 parentId 当成树。`call_edges` 保存必要调用位置，`call_paths` 保存一条调查路径，`path_steps(path_id, step_index)` 保存该路径中的顺序与证据。同一 edge 可以出现在不同路径，结论写到路径上下文，不写成全局 edge 结论。

Java 语法解析使用 java-parser 3.0.1，按接收者类型、方法名、参数个数且唯一候选时建立候选联系；同参数个数重载、动态派发和外部调用可能无法解析，保留 unresolved。以危险 API 为起点有界反向展开，不先枚举全仓库所有路径。

默认最多 100 个风险结果、16 层深度、512 个展开节点、100 条路径；单 Java 文件 CST 解析上限 256KiB，必要边最多 1000，模型审阅最多 16 步。达到限制会保留 partial/truncated/警告，详细算法与准确约束见 [工作台学习指南](04.SCAN-UI-调用链预处理与工作台学习指南.md)。

`scan_runs` 保存扫描范围和结果；`path_attempts` 记录每次领取。结果提交必须匹配当前 attempt，过期请求不能覆盖新结果；启动恢复会把遗留活动任务标记为中断，默认不自动再请求模型。

风险值使用 NULL=未知、0=防护阻断、1=证据支持风险。失败/未解析不能写 0。统计通过 SQL 按路径数、`COUNT(DISTINCT sink_edge_id)` 计数，不能把共享步骤总数当漏洞数。前端每 2 秒读取数据库刷新，不通过消息数量模拟进度。
