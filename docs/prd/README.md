# pi-audit-harness 需求看板

当前以功能流程组织为 15 个父需求：P0 5 项、P1 7 项、P2 3 项。原 59 项细节完整保留为子需求。

- P0：项目构建、源码仓库输入、Agent 分析流程、调用链详情与审计结果、报告输出与主流程验收。
- P1：模型与项目配置、模板、查询工具、交互与结果、恢复、安全、质量与开源交付增强。
- P2：平台与仓库、分析引擎、协作与报告扩展。

页面保留需求总览与需求列表。右侧详情覆盖 60% 页面，不改变列表布局；展开子需求查看验收和实现备注。搜索包含子需求内容。

以 index.html 和 requirements.json 为当前范围；旧 Markdown PRD 仅作为背景。页面为静态需求定义，不代表功能已经实现。

职责按前端、后端、前后端协作划分，不按个人身份划分。

2026-10-18 新增“重要设计”看板：调用链状态机、结果回调一致性、短期会话与检查点恢复。ldb 暂按 LevelDB 理解，ZSet 需上层实现；恢复仍为 P1，具体选型与提升优先级待确认。

会话快照方案已对齐：每个 sessionId 一个逻辑 ZSet，score 使用唯一递增 checkpoint，member 直接保存完整会话 JSON，按 score 降序读取最新有效快照。LevelDB 以有序键与反向迭代提供适配。
