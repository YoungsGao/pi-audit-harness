# MOD-02 / MOD-04 / SRC-03 / SCAN-02 设计

需求依据：`docs/prd/requirements.json` 中四项需求的全部验收条件。沿用 Electron / React / TypeScript 本地服务与 SQLite，不迁移架构。

## 方案选择

采用 SQLite 保存只读 Java 源码快照：现有单任务源码上限为 20MiB，可以使清单、文件原始字节与任务绑定在一个事务中持久化。备选的磁盘目录加只读属性需要另行处理文件与数据库的跨资源一致性；仅保存指纹无法满足旧证据不漂移，因而不采用。

## 四项交付

1. **MOD-02**：模型配置页的新建配置区域和常驻帮助入口均可打开 OpenRouter 教程，覆盖账号、API Key、Base URL、占位模型 ID、额度及常见错误；官方链接经过固定白名单打开。没有自动模型发现或切换。
2. **SRC-03**：预处理创建任务时保存独立快照 ID、逐文件 SHA-256、Java 原始字节、来源版本和明确的忽略策略。后续任务取证全部读取绑定快照并校验摘要。快照没有修改接口，数据库约束阻止修改；源目录变化不影响旧任务。新源码需重新登记和新建任务。历史任务未保存文件时明确提示需要新任务，不能从当前磁盘补造旧快照。
3. **MOD-04**：服务端提供发送范围预览与明确授权接口。范围绑定项目、任务快照、目标 Base URL、模型 ID、配置版本及内容类别；同一范围授权可复用。单路径、批量队列和 SSE 启动均在调用模型前强制检查；未授权显示确认内容后由用户选择。范围改变必须重新确认。实际执行配置与授权一致性再次校验，并保存发送审计记录。连通性 ping 无项目源码，不触发该授权。
4. **SCAN-02**：审计页按当前任务快照填写相对文件路径、行号、可选函数标识、规则和调查说明。后端核实文件及位置，保留手工来源记录，加入现有 pending 路径、Agent 取证、SSE、结果和报告流程；无效位置明确拒绝。手工位置只是待调查候选，不能自动成为已成立漏洞；入口或传播证据不足保持 unknown。
