# 03 数据模型与持久化

更新：2026-11-12。当前 SQLite schema **v15：21 表、244 字段、24 组外键、16 显式索引、19 触发器**。v1—v14 迁移保持原样，v15 将 33 表合并为 21 表。完整映射见 [19 表合并](19.数据库表合并与工程简化.md)，逐字段定义和 ER 图见 [18 数据库设计](18.数据库表设计与ER图汇报.md)。

## 存储方式

服务进程使用 Node DatabaseSync，全部业务表位于应用数据根目录的 storage/audit.sqlite3。WAL/SHM 是 SQLite 日志辅助文件。Java 快照内容为 BLOB；JSON 为 TEXT 列。CodeGraph 制品、原生 Pi 检查点和报告正文位于应用管理目录，数据库记录身份、位置和摘要。API Key 在系统凭据库。

用户值使用绑定参数。写事务使用 BEGIN IMMEDIATE，回调只做同步 SQL，不跨网络等待；失败整次回滚。get() 使用原生单行查询。外键、风险三态 CHECK、必要的冻结和版本不可变约束保留。

MCP 服务配置使用应用数据目录的 mcp/servers.json 与 mcp/runtime.json，没有增加 SQL 表；接口见[20 Python MCP](20.Python本地MCP服务与客户端管理.md)。

## 关系与状态

调用边保存共享事实，path_steps(path_id,step_index) 保存各路径自己的传播判断。两条路径共享 Sink 也能得出不同结论。call_paths.status 是调查进度；verdict/dangerous 为 unknown/NULL、safe/0、dangerous/1。失败和未覆盖不等于安全。

analysis_sessions 的 UNIQUE(chain_id,attempt_id) 保存全部尝试，最新尝试按 attempt_id 倒序获取，phase 由 state 派生。领取、恢复关联、路径清空和 queued/analyzing 事件同事务保存。

audit_events.seq 是任务日志序号，session_seq 是会话 SSE 游标，不能互换。queued 及无法匹配的旧帧没有任务 seq。具有 SSE 投影的事件将公开 frame 保存在 body_json；普通任务事件保存 {payload}。一条工具输出只落一行、一份 JSON。客户端 SSE 格式保持兼容。

路径结果、步骤证据、任务/会话状态和终态事件同事务提交。SSE 过期只调整 min_event_id，不删除共用审计记录，因此过期不等于释放磁盘空间。

## 固定材料、请求和恢复

audit_runs.snapshot_id 引用固定快照；review_json/review_hash 冻结审查材料；graph_json/graph_hash 冻结图身份。冻结后不能替换内容。列表查询显式选列，避免反复加载大的图 JSON。

model_requests 对新生产请求只保留一行：授权创建 ID，预算登记复用 ID 并补充 journey/epoch，响应补充 received 和 usage，未确认请求记 uncertain。authorized 只表示授权登记，不证明送达。旧两张请求表没有共用 ID，迁移保留两类事实而不猜测配对；报告按 journey_id 统计执行请求，按 config_id 展示发送目标。

tool_receipts 用 (journey_id,request_key) 去重。基础读取键为 step:N，MCP 为规范化请求摘要。恢复仍核对固定原文、绑定、预算和检查点。path_recovery 是当前连续执行，analysis_sessions 是历史尝试，保留不同职责。

## 迁移与重试

DDL、数据复制、删除旧表、迁移账本和 user_version 原子提交；失败回滚。无会话的历史尝试补为保留原时间/错误码的会话，不伪造事件。原 SSE ID、公开 JSON 和过期窗口保留。旧程序不能回写 v15 库。

只有 SQLite BUSY/LOCKED 才最多额外重试两次，分别等待 50/100ms；主键、外键、CHECK、触发器和 SQL 错误立即返回。保留参数绑定、归属校验、冻结材料、发送范围、原文证据和停止屏障。
