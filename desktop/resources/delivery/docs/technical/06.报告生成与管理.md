# 06 报告生成与管理

更新：2026-10-29。实现 REP-01～REP-04，并纳入 QA-04 客户端至报告的端到端验证；支持独立人工结论、固定源码、三维筛选、JSON与阶段结果。

## 输入与快照

兼容生成接收projectId/runId；新preview接收任务身份与filter，export另带format和expectedSnapshotKey；打开/另存只接收projectId/runId/reportId。前端不能提交任意HTML、文件路径、统计或风险结论。后端验证作用域，从同一SQLite事务快照读取项目、任务、路径、步骤、证据、人工记录和统计。

报告不依赖页面临时状态，不通过重新读取磁盘源码替换旧证据。HTML 和 reports.summary_json 使用相同快照，后续重试分析不自动修改旧报告。

预览和生成复用savedReportSnapshot；结果先脱敏，再排除generatedAt计算snapshotKey。生成重读后与expectedSnapshotKey比较，变化则登记failed/REPORT_SNAPSHOT_CHANGED，提示刷新。HTML和JSON都保留同一口径的机器详情及独立人工记录。具体契约、JSON v1结构与保存边界见 [11 交互与复核导出](11.交互路径图人工复核与结果导出.md)。

报告同时保存任务 snapshotId、文件摘要、忽略范围、手工位置与调查说明，以及 source_transmissions 的实际配置和 SDK 可观察模型标识。请求前记录不构成远端送达证明；无法得知的上游路由不补造。历史任务缺源码快照时明确标记。详见 [08 四项增强](08.配置授权快照与手工调查.md)。

报告还保存任务 reviewConfig：模板全文/版本、项目要求和摘要，保留自定义知识未经验证说明；后续编辑不更新旧报告。详见 [09 模板与审查配置](09.审计知识模板与项目审查配置.md)。

## Pi 报告命令

服务使用真实 Pi 1.2.0 扩展注册并执行 `/report projectId runId`，处理器读取已保存快照并调用固定 HTML 模板。报告使用独立 PiRuntime，不读取审计模型凭据，禁止 provider 请求和模型发现网络访问，不占用正在审阅的 runtime。

命令成功以扩展无错误、实际产物存在、文件校验和数据库提交共同确认，不能仅凭 session.prompt 返回判定成功。模型不可达时仍能汇总已经保存的结果，但不能把原分析失败包装成成功审计。

## 统计与报告类型

| 字段 | 口径 |
| --- | --- |
| dangerous | 成立风险路径，按不同 pathId 计数 |
| riskPoints | 成立风险路径按 sink_edge_id/rule_id 组合去重 |
| safe | 当前路径有阻断证据 |
| unknown | 风险未知，包含待办、分析中、失败和证据不足等情况 |
| pending/analyzing/completed/failed/unresolved/invalid | 调查状态的另一维细分 |
| sinks | 候选 Sink 数，不是已成立漏洞数 |

dangerous + safe + unknown = paths。调查状态不能再与风险维度相加。两个入口到达同一 Sink 时，可有两条危险路径但仅一个风险点。

仍有 unknown、待办、失败、分析中、部分覆盖或相关扫描告警时标记阶段报告。任务执行 completed 不代表完整安全结论；旧报告未保存的风险点数和文件摘要保持缺失，不伪造为零。

filter按机器verdict、调查pathStatus、人工reviewStatus取交集。statistics为所选路径，allStatistics保留任务整体，reviewCounts独立统计人工状态；stale计数与四种状态重叠。stageReasons保留全任务缺口、任务结束/故障、截断、筛选范围和过期复核。筛选子集或0条结果都不代表全项目安全。

## 文件与登记生命周期

RUN-01/RUN-02补充recovery段：控制状态、所选路径的请求记录/未确认数量、epoch/state与最近恢复来源。HTML和JSON保持相同口径，不含原生会话正文、任意活动文件路径或凭据。停止报告保留RUN_USER_STOP、unknown和未完成范围，生成不调用模型。请求记录不等于供应商账单，见[12 停止与恢复](12.任务停止与可验证会话恢复.md)。

1. 服务产生 reportId 与应用报告目录中的固定文件名，先登记 pending。
2. 同一快照生成转义后的HTML或JSON；快照上限15MiB/1000条路径、产物20MiB，超限不静默截断。
3. 独占临时文件写入，rename 发布，计算 SHA-256。
4. 校验目录和文件为应用持有的普通路径，无链接替换且内容摘要一致。
5. 事务提交 ready、时间、快照、摘要和报告事件；失败则保存 failed。

文件系统与 SQLite 不能组成同一个事务。状态不可写时返回 REPORT_PERSISTENCE_FAILED；服务重启将未结束报告收敛为失败，不能宣称完整跨资源原子性或无孤立文件风险。

## 接口与打开边界

| 接口/动作 | 行为 |
| --- | --- |
| `POST /reports/generate` | 按已保存任务生成独立报告 |
| `POST /reports/preview` | 按任务和三维filter返回同口径统计、阶段原因及snapshotKey |
| `POST /reports/export` | 指定html/json、filter、expectedSnapshotKey，登记并形成固定产物 |
| `POST /reports/list` | 指定项目/任务查询最近最多 100 条登记 |
| `POST /reports/file` | 只返回已登记、ready 且摘要可校验的产物 |
| preload openReport | 主进程按 ID 查登记，再核对归属、普通文件和 SHA-256 后请求系统打开 |
| preload saveReport | 主进程验证登记，原生对话框选位置，校验扩展名/目录后复制；取消不删除登记 |

报告文本先脱敏再 HTML 转义，使用固定模板和内容安全限制。路径虽可显示，打开时仍只传标识。丢失、被修改、跨项目、目录联接或旧记录缺校验摘要时明确拒绝并要求重新生成。

JSON使用固定序列化器并转义尖括号、&、U+2028/U+2029；API Key不进入报告读取流程。人工备注和原文仍作为文本，不执行标签。另存目的地只来自主进程原生对话框，拒绝应用运行目录、链接和非普通文件，验证原摘要后用独占临时文件发布副本；HTML可以打开，JSON通过另存交给用户工具处理。
