# 19 数据库表合并与工程简化

更新：2026-11-12。schema v15 实现 **33 → 21 表，减少约 36%**，字段 295 → 244。API、SSE frame、模型工具协议和报告格式兼容。结构与 ER 图见 [18 数据库设计](18.数据库表设计与ER图汇报.md)。

## 1. 合并原则与映射

一对一信息归入其所属实体；同一事件、请求和回执只维护一份账本；独立数量、独立历史的数据继续分表。删除 15 张旧表、新增 3 张共用账本，净减少 12 张。没有增加兼容视图和写入转发触发器。

| 原表 | v15 归属 | 内容 |
| --- | --- | --- |
| source_imports | projects | source_key/stamp、文件数、字节数、登记时间 |
| project_review_settings | projects.review_json | 完整要求及其独立 revision |
| scan_runs | audit_runs | scan_state、统计、告警、扫描起止与错误码 |
| run_snapshots | audit_runs.snapshot_id | 固定快照引用，多个任务仍可复用快照 |
| run_review_configs | audit_runs.review_json/review_hash | 冻结审查全文，原 createdAt 在 JSON 内 |
| run_graph_bindings | audit_runs.graph_json/graph_hash/graph_created_at | 固定查询图身份 |
| run_controls | audit_runs | control_state/revision/updated_at、model_json |
| manual_risk_points | call_paths.manual_points_json | 完整数组，保留旧 pointId/createdAt |
| path_attempts | analysis_sessions | 每次尝试即一个会话，phase 从 state 派生 |
| analysis_events + stream_events | audit_events | 共用 payload，独立任务 seq 与会话 session_seq |
| recovery_tools + recovery_mcp_tools | tool_receipts | 工具名、请求键、回执、摘要、epoch |
| source_transmissions + recovery_requests | model_requests | 新请求 ID 贯穿授权、执行、响应、恢复与用量 |

21 表中包含迁移账本、模型选择和凭据清理等基础设施。调用边、路径、步骤、模板版本、人工复核与安全检查点仍有一对多或历史价值，继续分开使查询和更新更直接。path_recovery 是当前连续调查，analysis_sessions 是每次尝试的历史，两者不能简单混成一行。

## 2. 事件只保存一次

appendEvent 计算脱敏、有界 payload 和可选 SSE 投影；在同一事务中写一次 audit_events，并同步更新会话状态。SSE 读取 body_json 中原公开 frame，任务日志读取其中 payload。普通任务事件没有 session；queued 只有 session_seq。公共 DTO 不暴露数据库新布局。

```sql
SELECT seq,session_seq,stream_event,type,status
FROM audit_events WHERE run_id=? ORDER BY time,event_id;
```

任务 seq 可以跨路径排序；session_seq 只能在指定 session 内使用。SSE 过期只更新 min_event_id，不删除共用审计事件；当前尚无自动清理审计记录的策略，不能宣称过期会释放磁盘空间。

## 3. 尝试与请求统一

领取在短事务中取最大 attempt_id + 1，插入新会话并修改路径。删除“最新尝试 UPSERT + 会话 INSERT”的双状态。结果提交仍检查活动会话、恢复 attempt/epoch 与停止状态。人工复核基线保持原 `{attempt,phase}` 形状，避免升级后错误地标为过期。

传输边界 authorizeModel 返回持久化请求 ID。RecoveryExecution.request 在一个事务里计预算、执行授权并关联同一 ID；失败回滚，不发送模型请求。

```text
发送确认 → model_requests(request_id)
             ↓ 同一行
预算/journey/epoch + started → received + usage 或 uncertain
```

authorized 表示授权登记，不证明请求已经送达。旧发送表和请求表没有共享 ID，仅凭相近时间无法可靠配对。迁移保留两类事实：执行记录有 journey，发送记录有 config；新生产请求同时拥有两类信息。跨版本统计不能把 model_requests 总行数当实际付费次数。报告按 journey_id 统计执行请求，按 config_id 展示发送范围。

## 4. 旧库迁移

v1—v14 SQL 与校验和保持不变。v15 在同一事务增加主表列、复制附属信息、迁移共用账本、删除旧表和更新版本；失败回滚全部 DDL 和数据。

历史事件按 payload、摘要、调用身份及顺序匹配；匹配记录保存一份。无法匹配的旧 SSE frame 单独保留，seq 为 NULL；原 session_seq、公开 JSON 和过期窗口不变。没有会话的历史尝试补为 legacy-attempt-… 会话，保存原时间和错误码，不伪造工具或模型事件。

快照引用保留外键和项目归属约束；任务审查与图材料首次写入后冻结。手工点保存为数组，迁移不丢弃一条路径上的多个历史点，UI 按原契约显示首个点。旧程序不能回写 v15 库。

本轮使用隔离库验证升级，没有直接改写正在使用的个人库。新代码启动后会对其应用数据目录执行迁移。

## 5. 减少的冗余检查与开销

- 删除重复事件写入、两套尝试状态、两套回执 SQL 和两套新请求台账。
- 源码注册与项目要求不再额外 JOIN；控制读取不再先查任务再查附表。
- 单行查询改用原生 get；任务列表显式选列，避免把图 JSON 随状态查询反复加载。
- 仅 BUSY/LOCKED 重试，最多额外两次，等待 50/100ms；确定的约束或 SQL 错误立即返回。
- Git 更新触发器只监听来源列，避免普通审查编辑或迁移被不完整的旧 Git 元数据阻止。

参数绑定、短事务、归属外键、风险三态、固定原文校验、发送范围确认和停止后的迟到写入屏障继续保留，它们直接支撑现有功能。
